Manifesto da Semana

Esta semana não desenvolvemos novas features. Paramos para respirar, olhar para o que construímos e torná-lo melhor. As duplas são formadas por um engenheiro de cada squad — conhecimento cruzado entre Atividades da Escola e Banco de Questões. Sem títulos de senioridade, sem hierarquia. Apenas engenheiros resolvendo problemas juntos, com as melhores ferramentas disponíveis. Designers participam das sessões de alinhamento e do Demo Day.

🌎 Você está em boa companhia

As melhores organizações de engenharia do mundo pausam features regularmente para focar em qualidade. A EEW é inspirada nessas práticas — especialmente no Fixit Week do Google.

🔴

Google — Fixit Weeks

Times inteiros pausam features para zerar bugs e dívida técnica. É de onde veio a ideia da EEW — foco total em qualidade, sem exceção.

🔵

Atlassian — ShipIt Days

Hackathon trimestral: 24h para entregar qualquer melhoria. Termina com demo e votação do time — exatamente o formato do nosso Demo Day.

🟢

LinkedIn — InDays

Dias trimestrais onde engenheiros trabalham no que quiserem: infra, ferramentas, qualidade, aprendizado. A origem do conceito de wishlist liberada.

🟤

Spotify — Hack Week

Semana anual de projetos livres com duplas cross-squad — sem entrega obrigatória de feature. A inspiração para misturar os dois times aqui.

🔵

Meta — Hackathon Culture

O botão de Like e outras features icônicas nasceram em hackathons internos. Autonomia + tempo = inovação real. O "move fast" começa com espaço pra pensar.

Demo Day 🎉🟢 Ao Vivo

O grande momento da semana. Cada dupla tem ~15 minutos para mostrar o que fez — sem burocracia, com orgulho. Não é apresentação corporativa: é contar uma história de antes e depois.

📋 Estrutura sugerida (~15 min/dupla)

1. O que vocês atacaram — qual era o problema ou a melhoria escolhida

2. O antes — como estava, por que incomodava

3. O depois — o que mudou, com números se tiver

4. O aprendizado da dupla — o que cada um aprendeu com o outro

💡 O que você pode mostrar

› Um PR aberto com a mudança — código fala por si

› A planilha SRE antes e depois (Não → Sim)

› Um gráfico de tempo de resposta ou cobertura de testes

› O README novo do repo vs o que tinha antes

› O Doc de Vitórias já preenchido

› Um terminal rodando os testes que não existiam na segunda

🏅 Votação no final

Após todas as apresentações, o time vota em categorias como "Melhoria mais impactante", "Dupla mais criativa" e "Melhor storytelling". Não tem prêmio físico — o reconhecimento do time já vale muito.

Para Desenvolvedores

Contexto é tudo

Sempre dê ao Claude o contexto do que está sendo construído, stack usada e restrições. Quanto mais contexto, melhor o resultado.

Peça revisão antes de commitar

Use /review para que o Claude analise segurança, performance e boas práticas antes de qualquer PR.

Agentes especializados

Use o agente Reverse Engineering para documentar código legado, Kotlin Lead para backend e TS Reviewer para frontend.

Testes primeiro

Peça ao Claude para gerar testes unitários para código existente. Depois revise e ajuste. É mais rápido que escrever do zero.

Não aceite cegamente

Sempre leia o que o Claude sugeriu. IA erra. Você é o responsável pelo código que vai para produção.

CLAUDE.md por repo

Crie um arquivo CLAUDE.md na raiz do repo com contexto do projeto. O Claude lê automaticamente.

❓ Perguntas Frequentes

E se a dupla não conseguir terminar tudo na semana?
Tudo bem. O objetivo não é zerar o checklist a qualquer custo — é fazer progresso real e com qualidade. Priorize pelo impacto: o que vai melhorar mais a vida da Ops e dos usuários? Comece por isso.
Como funcionam os repos que não são "da dupla"?
Os repos listados em cada dupla são a responsabilidade primária. Mas se outra dupla precisar de ajuda ou se você tiver expertise em outro repo, colabore livremente — o cruzamento de conhecimento é exatamente o objetivo.
Eu nunca usei Claude Code. Como começo?
O Workshop de terça-feira (31/03 às 09:30) cobre do zero ao avançado. Antes disso, instale o Claude Code (npm i -g @anthropic-ai/claude-code) e leia a seção de boas práticas deste manual. Em 30 minutos você já está operacional.
O que é esperado dos designers na semana?
Os designers participam das sessões coletivas: Kick-off, Voz da Ponta, README Humano, Visão Q2, Demo Day e Happy Hour. O foco da semana é engenharia — a presença dos designers nas sessões de alinhamento é para manter a visão de produto e experiência conectada ao que está sendo construído.
